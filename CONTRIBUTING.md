# Contributing to ama-mobstack

Thanks for helping. A few rules keep this repository useful and safe.

1. **Open an issue first** for anything larger than a typo, so the approach can be agreed.
2. **One change per pull request.** Explain what it does and how you tested it.
3. **No private data.** No secrets, keys, personal data or unpublished mentor content, ever.
4. **Be accurate.** Label proposals as proposals. Do not describe untested behaviour as working.
5. **Upstream when it fits.** If a pattern is useful beyond HAMAL, we may propose it to the relevant Hanzo project; your authorship is kept.
